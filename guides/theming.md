# Theming and assets

## Tokens

The default theme follows the admin UI kit in the design reference: ten semantic colours
(bg, surface, border, text, muted, brand, ok, info, warn, danger) plus derived shades,
6 px radius for controls and 8 px for cards, a 4 px spacing scale, 13 px body text and
IBM Plex Sans / Plex Mono. Every value is a CSS custom property defined in
`assets/css/alkemist-theme.css`; override them in any stylesheet loaded after Alkemist's,
no rebuild required:

```css
:root {
  --ak-brand: #C8102E;        /* the brand name in the sidebar, and nothing else */
  --ak-primary: #18181B;      /* primary buttons, active tab, current page */
  --ak-radius: 6px;
  --ak-sidebar-w: 232px;
  --ak-font-sans: "Inter", ui-sans-serif, system-ui, sans-serif;
}
```

Dark mode follows `prefers-color-scheme`; `<html class="dark">` or `class="light"` forces
one. The optional `AlkemistTheme` hook toggles and persists the choice.

IBM Plex is shipped with the prebuilt bundle (latin subset, SIL Open Font License, see
`priv/static/assets/fonts/OFL.txt`). Mode B hosts load their own font files or override
`--ak-font-sans` and `--ak-font-mono`.

## Page anatomy

- **Sidebar**: brand (`title`, `subtitle`, `logo`), navigation from the router (`menu/2`;
  `parent:` becomes an uppercase group, `icon:` a `hero-*` icon), account footer
  (`current_user_name` from the authorization provider, `environment`, `sign_out`).
- **Header band**: back link, title (show pages: `title:` option), `description:`,
  actions (secondary buttons, one primary), tabs.
- **Index**: search box (the `primary: true` filter) and a dropdown button per other
  filter, scope tabs with counts, the table with a "⋯" menu per row, and the pagination bar
  inside the table card.
- **Show**: a details card from `rows`, panels from `show_panels` (a `tab:` puts a panel
  on its own tab), and `sidebars` as cards in the right column.
- **Forms**: field groups as cards, 32 px inputs, errors under the field and summarised on
  top; Save (primary) and Cancel (ghost).
- **Feedback**: flashes as toasts in the bottom right corner; dashed empty states.

Domain-specific pieces (status badges for your own fields, masked identifiers, provider
cards) belong in your application: format cells with a column's `format:` function using
`Alkemist.Components.Core.badge/1`, and add cards with `sidebars`/`show_panels` or your
theme module.

## Stable classes

Components use `.ak-*` classes (`.ak-shell`, `.ak-sidebar`, `.ak-nav__link`,
`.ak-page-header`, `.ak-card`, `.ak-details`, `.ak-table`, `.ak-th`, `.ak-td`, `.ak-btn`,
`.ak-btn--primary|secondary|ghost|danger`, `.ak-badge--ok|info|warn|danger`, `.ak-tabs`,
`.ak-filters`, `.ak-filter-button`, `.ak-input`, `.ak-field`, `.ak-form`, `.ak-nested`,
`.ak-table-foot`, `.ak-page`, `.ak-toast`, `.ak-empty`), defined in
`assets/css/alkemist-components.css`. Target them from your CSS; utility classes
inside Alkemist's templates are an implementation detail.

## Mode A: prebuilt bundle (default)

```elixir
plug Plug.Static, at: "/alkemist", from: :alkemist, gzip: true, only: ~w(assets)
```

Your theme module may use any `.ak-*` class and any Tailwind utility that appears in
Alkemist's own templates; utilities Alkemist does not use are not in the bundle. Icons:
the Heroicons Alkemist ships are inline SVG (`Alkemist.Components.Icons.builtin/0`).

## Mode B: your own Tailwind build

Add to `assets/css/app.css`:

```css
@import "tailwindcss";
@source "../../deps/alkemist/lib";
@import "../../deps/alkemist/assets/css/alkemist-theme.css";
@import "../../deps/alkemist/assets/css/alkemist-components.css";
```

and to `assets/js/app.js`:

```js
import * as AlkemistHooks from "../../deps/alkemist/assets/js/hooks/index.js"
import { mount } from "../../deps/alkemist/assets/js/alkemist.js"   // dead views
// or: new LiveSocket("/live", Socket, {hooks: {...AlkemistHooks}})
```

then point Alkemist at your bundle:

```elixir
config :my_app, Alkemist, assets: [css: "/assets/app.css", js: "/assets/app.js"]
```

Now every utility and `hero-*` icon class used in your theme module is generated by your
build. Do not also load the prebuilt bundle (phoenix_html.js would be loaded twice).

## Theme module

```elixir
defmodule MyAppWeb.AlkemistTheme do
  use Alkemist.Theme

  @impl true
  def app(assigns) do
    ~H"""
    <.shell>
      <:sidebar>
        <.brand_link title="My App" subtitle="Admin" href="/admin" />
        <Theme.sidebar alkemist_app={@alkemist_app} conn={@conn} current_path={@current_path} menu_items={Alkemist.Menu.items(@conn)} />
      </:sidebar>
      {render_slot(@inner_block)}
      <Theme.flash_group alkemist_app={@alkemist_app} flash={@flash} />
    </.shell>
    """
  end
end
```

Override only what you need; `Alkemist.Theme` lists every callback. A controller can use a
different theme with `render_index(conn, params, theme: OtherTheme)`.
